# Glass rendering refactor audit (before changes)

This audit records the rendering risks found before the implementation patch.

1. **`Modifier.blur()` stand-ins:** none found in the Kotlin source. Blur currently uses `RenderEffect.createBlurEffect` in `designsystem/glass/src/main/kotlin/com/glassmail/designsystem/glass/GlassMaterial.kt:337`.
2. **Per-item captures:** `SettingsScreen` creates and records `previewLayer` in a `LazyColumn` item at `app/src/main/kotlin/com/glassmail/app/SettingsScreen.kt:257-279`. `GlassLabScreen` similarly creates `labBackdropLayer` in a lazy item at `app/src/main/kotlin/com/glassmail/app/GlassLabScreen.kt:205-228`. These are two isolated previews, not per-mail-row captures, but they duplicate capture infrastructure inside lazy content.
3. **Recursive capture risk:** the root `GlassProvider` records the complete `NavHost` at `app/src/main/kotlin/com/glassmail/app/GlassMailApp.kt:191-260`. No current call inside that subtree samples the root layer: mail rows and reader surfaces pass `backdropSampling = false`; Settings and Glass Lab use explicitly isolated preview layers. The generic `GlassSurface` defaults to `backdropSampling = true` at `designsystem/glass/src/main/kotlin/com/glassmail/designsystem/glass/GlassMaterial.kt:269-278` and samples the ambient provider at `:387-399`, so that default is unsafe for future calls inside the recorded subtree. The floating dock is composed after the provider at `GlassMailApp.kt:268-286`.
4. **Shader lifetime:** the current `RuntimeShader` is remembered at `GlassMaterial.kt:291-298`; it is not rebuilt on every recomposition. It is a single embedded shader string rather than independently selectable shader sources.
5. **Position updates:** surface and provider positions are read with `onGloballyPositioned` at `GlassMaterial.kt:367-371` and `GlassBackdrop.kt:58-63`, so placement changes are observed. However, the shader has no `offset` uniform; alignment relies on translating the shared layer at `GlassMaterial.kt:395-398`.
6. **API guards:** `RuntimeShader` construction is guarded by API 33 at `GlassMaterial.kt:291-298`; `RenderEffect` creation is guarded by API 31 at `:337-355`. The selected tier itself is not clamped, so FULL/BALANCED can be requested below API 33 and silently degrade.
7. **Unrelated invalidation:** `GlassProvider` increments Compose state from its draw callback at `GlassBackdrop.kt:69`, and publishes that state to descendants at `:72-77`. The capture wraps the entire screen, including interactive controls, so child visual state changes can also redraw/re-record the screen layer.
8. **Insets and edges:** the root capture fills the app box, while the top capsule applies `statusBarsPadding()` inside its surface modifier at `app/src/main/kotlin/com/glassmail/app/GlassMailChrome.kt:41-44`. The dock applies `navigationBarsPadding()` outside the glass surface at `designsystem/src/main/kotlin/com/glassmail/designsystem/GlassChrome.kt:108-113`, which can leave the system-bar region outside the glass material and expose edge seams.

The audit distinguishes active behavior from latent API risks; the patch below prevents ambient backdrop sampling while content is being recorded and exposes the single root layer explicitly to foreground glass.

## Post-patch verification

- `./gradlew :app:assembleDebug` completed successfully.
- On a Pixel 9a / API 35, ten repeated taps on the already-selected **All** filter produced **0 additional backdrop records** after the final build had settled (the diagnostic was at frame 2 before the taps).
- Instrumenting the pre-patch provider on the same device showed **1,582 records** during the ten-tap interval (frame 3,415 to 4,997 over about 13.6 seconds). The old draw callback incremented Compose state on every draw, so it continuously re-recorded even while idle; this count is the whole interaction window, not an incremental count attributable only to the taps.
- The final device launch produced no `GlassMailGlass` AGSL initialization warning and no app crash. Its saved legacy `LIQUID` preference resolved to FULL, so the full AGSL variant was initialized on-device. The device log counter is opt-in via `adb shell setprop log.tag.GlassBackdrop DEBUG`.
- Sampling now compares the requested source with `LocalBackdropCaptureSource`; a surface cannot sample the exact `GraphicsLayer` that is currently recording it. The floating dock and command palette use the shared root source from sibling layers. Settings and Lab keep one isolated pattern capture apiece for their single live preview viewport.
- The quality resolver clamps before runtime shader/effect setup, migrates saved legacy values, and Settings only offers tiers valid for the current SDK. The app and existing modules still declare `minSdk = 34`, so API 31/32 and pre-31 fallbacks are implemented but cannot currently be exercised by installing this app on those OS versions without a separate minimum-SDK change.

The root provider still records the screen `NavHost` as the scrolling/background image, including glass surfaces that do not sample that root source. All surfaces that do sample a source are outside that source's recorded subtree; the isolated Settings/Lab previews sample only their pattern captures, which exclude the preview surfaces themselves.
